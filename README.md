# PARCEL PANIC — 컨베이어 대작전

벨트와 처리기를 배치해 주문을 제시간에 출고하는 물류 퍼즐입니다.

[게임 실행](https://hyungminyoon1.github.io/parcel-panic/) · [WEB LAB](https://hyungminyoon1.github.io/web-lab/) · [소스](https://github.com/HyungminYoon1/parcel-panic)

## 게임

기본 연습, 기존 계약 1–12, 검수·포장 계약 13, 재검수 최종 계약 14. 기존 캠페인의 지도·주문·마감은 보존합니다.

- 벨트 1원, FIFO 버퍼 3원/3개, 문자 분류기 4원. R 직진·B 우회전·G 좌회전.
- 처리기 4원: 지정 칸의 공정을 정해진 박자만큼 수행합니다. 공정 분기기 4원: 다음 공정이 수선이면 우회전, 나머지는 직진.
- 반품은 검수 → 수선 → 같은 검수기로 복귀 → 포장. 일반 주문과 합류하며 공정을 빠뜨리면 출고에 실패합니다.
- 급행 → 도착 박자 → 주문 번호 순의 합류. 박자 시작에 차 있던 칸에는 이동하지 않습니다. 밀린 화물도 마감 시계가 계속 흐릅니다.
- 정비의 시작/끝 박자는 모두 정지합니다. 마감 박자 출고는 유효하며 다음 박자는 출고 전에 실패합니다.

## 조작

설비와 방향을 고른 뒤 칸 클릭/드래그. 터치는 칸을 선택한 뒤 설치합니다. 방향키 이동, Space 설치, R 새 설비 방향, E/우클릭 기존 설비 회전, Delete 철거, Z/Y 취소·복구, P 가동·정지. 모바일은 전체 보기, 100–300% 확대, 양방향 밀기와 칸 이동 패드를 제공합니다.

기본 연습은 선택된 7열 4행에 → 분류기를 설치하고 가동하면 실제 주문 두 개를 출고합니다. 일반 운행 리셋은 설비를 유지합니다. 최종 계약 기록 모드의 ‘새 기록’은 빈 설계로 다시 시작합니다.

## 점수와 기기 저장

성공 점수 = max(0, 5000 − 완료 박자×12 − 설비 비용×15 − 화물 대기×2). 처리 중인 박자도 대기에 포함합니다. 재생 속도·실제 시간·재시도 횟수는 점수와 무관합니다.

설계·현재 계약·독립 최고 기록을 이 기기의 `parcel-panic-save-v2`에 최대 131072문자로 저장합니다. 새로고침과 복원은 설계 상태로 돌아오며 자동 가동하지 않습니다. 저장 거부·용량 초과 시 화면 안에서 계속 플레이할 수 있습니다. 저장 삭제는 이 게임의 기록만 지웁니다.

힌트를 본 설계는 리셋·복원해도 연습이며, 독립 기록과 갤러리 완료에 포함하지 않습니다. ‘새 도전’은 시작 설비에서 다시 시작합니다. 기본 연습은 완료 개수에 포함하지 않습니다.

갤러리용 `web-lab-progress-v1`에는 독립 완수 개수/전체 14/실제 갱신 시각만 공유합니다. 다른 앱의 비공개 데이터는 읽지 않습니다. 일반 플레이는 서버에 전송하지 않습니다. 공개 기록 기능만 별도 API에 연결하며 호스팅 로그는 앱 처리와 별개입니다.

## 최종 계약 공개 기록

`dist/src/ranked.js`: `RULES_VERSION="parcel-2"`, `CHALLENGE_ID="rework-final-v2"`, `rankingDefinition()`, `replayRanked(actions)`. 최고 계약 14의 빈 설계에서 실제 설치/회전/취소/복구/초기화/start/tick을 재생합니다. 한 기록은 최대 512개 입력, UTF-8 48KiB, 한 번의 가동입니다. 틀린 명령·클라이언트 점수·결과 스냅샷·힌트·리셋은 거부합니다. 새 기록 횟수는 제한하지 않습니다. 동점 비교 값은 `[완료 박자, 설비 비용, 대기]` 오름차순입니다.

하단 **공개 기록 도전**은 최종 계약의 빈 설계에서 시작하고 힌트를 잠급니다. 완료 뒤 등록을 누르면 서버가 실제 설치·운행 명령을 다시 실행하여 최고 기록을 공개합니다. 재생 속도는 점수와 무관하며 자동 게시하지 않습니다. `rankingAdapter`가 실제 입력을 캡처하고 `ranking-client.js`가 API 조작을 담당합니다.

닉네임은 선택 사항입니다. 서버에는 익명 식별값·검증용 명령·최고 기록을 저장하며 마지막 활동 후 180일 보관합니다. 등록 권한은 이 브라우저의 별도 키에 저장됩니다. **공개 기록 삭제**는 이 식별값으로 등록한 PARCEL PANIC과 NEON TACTICS의 공개 기록을 함께 삭제하며 기기 내 플레이 기록은 유지합니다. 브라우저 저장만 지우면 삭제 권한도 잃을 수 있습니다. 서버 검증은 사람만 플레이했거나 한 사람당 한 계정이라는 보장은 아닙니다.

[랭킹 서버](https://github.com/HyungminYoon1/web-lab-ranking) · [API 상태](https://web-lab-ranking.hyeongmin92.workers.dev/health)

일반 연습 리플레이는 최대 2048개 입력/8회 가동/200000문자이며 별도 JSON으로 내보낼 수 있습니다. 격자는 최대 11×9 / 9×11(연습·13은 9×7), 주문 최대 29, 계약당 최대 180박자, 설계 취소/복구 최대 80 상태입니다. 기준 재생 420ms/박자, 1/2/4× 속도, 프레임당 최대 3박자.

## 실행 및 검증

Node.js 22 이상, 외부 패키지 설치 없음.

```sh
npm run dev -- 0
npm test
npm run check
node tools/benchmark-ranked.mjs
```

개발 서버는 127.0.0.1에서 dist만 제공합니다. 기존 23개를 유지한 42개 테스트는 기존 출고 순서/시간, 순서별 공정·검수기 재방문, 실제 실패, 입력 리플레이·제한, 저장 손상/거부/복원과 다른 앱 요약 보존을 검증합니다.

새 계약 합법 모델 해답: 연습 15박자/2건, 13번 83박자/12건, 14번 142박자/24건/49원/1457점. 복귀 버퍼 하나를 벨트로 바꾼 별도 합법 해답은 47원/1487점입니다. 해답은 공개 게임이 import하지 않는 `tools/advanced-witnesses.mjs`에만 둡니다.

이번 변경의 브라우저 E2E·스크린샷·공개 배포는 메인 통합 담당자가 검증합니다. 기존 브라우저 기록은 이전 버전의 증거입니다. 실제 모바일 하드웨어·사람의 난도/재미·Worker CPU 제한 충족은 미검증입니다.
